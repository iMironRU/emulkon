# Компонента-драйвер Эмулкон (Native API, C++)

Драйвер подключаемого оборудования для БПО. С точки зрения 1С это обычный драйвер ККТ,
эквайрингового терминала, весов (обычных и с печатью этикеток) и принтеров (чеков и этикеток)
(требования к драйверам 4.8, ревизия 4008): в пакете типы
«ККТ,ЭквайринговыйТерминал,ЭлектронныеВесы,ВесыСПечатьюЭтикеток,ПринтерЧеков,ПринтерЭтикеток,СканерШтрихкода,СчитывательМагнитныхКарт,ДисплейПокупателя,ТерминалСбораДанных,СчитывательRFID,УстройствоРаспознавания» (все 12 типов),
БПО заводит драйвер для каждого типа. Внутри — тонкий прокси к серверу эмуляции
(ARCHITECTURE §4.1). Протокол — [docs/protocol.md](../docs/protocol.md).

## Как устроена

| Файл | Что делает |
|---|---|
| `src/driver.*` | класс `EmulkonDriver : IComponentBase` — то, что вызывает 1С |
| `src/methods.*` | таблица методов: имена (англ./рус.), число параметров, кто обслуживает вызов |
| `src/device_client.*` | Device API: сессия, вызов метода, повторы с тем же `request_id` |
| `src/http_winhttp.cpp` | HTTP/HTTPS через системный WinHTTP; длинный GET потока событий с отменой из другого потока |
| `src/events.*` | события устройства: поток SSE с сервера → `ExternalEvent` в 1С (фоновый поток на устройство) |
| `src/json.*`, `src/text.*` | JSON без зависимостей, UTF-8↔UTF-16, разбор `ConnectionParameters` |
| `src/update.*`, `src/update_win.cpp` | самообновление: версии, SHA-256, кэш обновлений, фоновое скачивание |
| `src/exports.cpp`, `emulkon.def` | экспорт `GetClassObject` и др. без декорирования; переадресация в новую DLL из кэша |
| `tests/unit.cpp` | модульные тесты ядра |
| `tests/harness.cpp` | стенд «как платформа 1С»: грузит DLL и вызывает методы через vtable |

**Кто обслуживает вызов:**

- **Сама компонента** — то, что БПО вызывает до подключения, когда адреса сервера ещё нет:
  `ПолучитьРевизиюИнтерфейса` (4008), `ПолучитьОписание` (XML с `IsEmulator="true"` и
  «ЭМУЛЯТОР» в названии), `ПараметрыОборудования` (настройки, см. ниже), дополнительные
  действия («Проверить обновление драйвера»), локализация. Сюда же `ПолучитьОшибку`: код и текст последней неуспешной операции
  компонента запоминает сама, из ответа сервера (`error_code`, `error_text`) или из сбоя связи.
- **`ПодключитьОборудование`** — открывает сессию на сервере, передаёт туда сам вызов
  (без токена в параметрах) и возвращает 1С свой DeviceID: `emulkon-1`, `emulkon-2`, …
- **`ТестированиеОборудования`** — пробная сессия по переданным параметрам. Если сервер
  недоступен — `False` и понятное описание.
- **Всё остальное** (методы ККТ, терминала, весов, принтеров) — на сервер по DeviceID из параметра 0. Обратно в
  параметры 1С записываются только изменённые позиции (выходные).
- **События устройства** (сканер, считыватель карт, весы, дисплей): после `ПодключитьОборудование`
  компонента держит поток `GET /api/v1/devices/{id}/events` в фоновом потоке и на каждое событие
  вызывает `ExternalEvent(DeviceID, имя, данные)`. Очередь платформы — 256 событий
  (`SetEventBufferDepth`). Обрыв — переподключение с курсором; `ОтключитьОборудование` и выгрузка
  компоненты закрывают поток и ждут его (docs/protocol.md §1.4).
- **Операции, которые ждут человека** (оплата, возврат и другие операции с картой, «Получить
  вес» — `waitsForPerson` в `src/methods.cpp`), ждут ответа сервера до 5 минут вместо `TimeoutMs`.
  Карту в это время «прикладывают» на экране терминала, вес вводят на экране весов.

**Настройки драйвера** (форма настройки оборудования в БПО):

| Параметр | По умолчанию | |
|---|---|---|
| Адрес сервера (`ServerURL`) | `http://127.0.0.1:8737` | http или https |
| Токен устройства (`DeviceToken`) | — | токен рабочего места (выдаётся в UI, место берётся из него) или `EMULKON_DEVICE_TOKEN` сервера; в журнал не уходит |
| Рабочее место (`WorkstationID`) | имя компьютера | идентификатор на сервере |
| Таймаут, мс (`TimeoutMs`) | 30000 | ожидание ответа на одну команду |
| Обновлять драйвер автоматически (`AutoUpdate`) | да | скачивать новую версию с сервера эмуляции |

**Связь.** При обрыве, таймауте или `503` вызов повторяется до трёх раз с тем же `request_id`:
сервер не выполнит метод второй раз и отдаст результат первого выполнения. При
`401 session_unknown` (сервер перезапущен) компонента молча открывает новую сессию.
Если связи нет, метод возвращает `False`, а `ПолучитьОшибку` — код 900 и текст
«Нет связи с сервером эмуляции <адрес>: <причина>.» (на «Нет связи» БПО показывает подсказку пользователю) и что
сделать: для адреса этого компьютера — Эмулкон здесь не запущен или не установлен (imiron.ru/emulkon) или общий сервер
команды (`ghcr.io/imironru/emulkon`); для другого адреса — проверить, что сервер запущен и открыт для касс в сети, и
адрес в настройках экземпляра (`noConnectionMessage`, issue #14).

Коды ошибок самой компоненты: 900 — нет связи, 901 — ответ не по протоколу,
902 — DeviceID не подключён, 903 — не поддерживается, 904 — неверные параметры.
Остальные коды приходят от модели на сервере (ККТ — [docs/models/kkt.md](../docs/models/kkt.md)).

## Самообновление

Подробно — [docs/protocol.md §1.5](../docs/protocol.md). Коротко:

- При подключении сервер сообщает, что есть DLL новее (каталог загрузок сервера). Компонента
  скачивает её в фоне в `%LOCALAPPDATA%\Emulkon\driver\<версия>\`, сверив размер и SHA-256.
- При следующей загрузке (перезапуск 1С) экспорты `GetClassObject`, `DestroyObject` и остальные
  переадресуются в самую новую DLL из кэша. Пакет в базе 1С переустанавливать не нужно.
- Вручную — кнопка «Проверить обновление драйвера» в форме настройки экземпляра. Результат
  приходит сообщением 1С. `ТестированиеОборудования` тоже пишет о новой версии.
- Выключить переход на DLL из кэша — переменная окружения `EMULKON_DRIVER_NO_UPDATE=1`;
  откатиться — удалить каталог версии из кэша.

DLL по-прежнему импортирует только `KERNEL32` и `WINHTTP`: SHA-256 реализован в `update.cpp`.

## Сборка (Windows)

Нужен ABI MSVC: в интерфейсах SDK 1С виртуальные деструкторы идут первыми, а у GCC/MinGW
они занимают в vtable два слота вместо одного. Поэтому сборка идёт clang-cl с CRT и
Windows SDK от Microsoft: локально — портативный тулчейн, в CI — Visual Studio и LLVM раннера ([cmake/toolchains](../cmake/toolchains)).
CRT линкуется статически: на кассе не нужен VC++ Redistributable.

```powershell
.\build.ps1                                  # x64 + x86, тесты, пакет в component\dist
.\build.ps1 -Server http://127.0.0.1:8737    # плюс сценарий ККТ на запущенном сервере
```

Тесты: `unit` (ядро, кэш обновлений на поддельном HTTP), `harness_offline`,
`harness_update_redirect` и `harness_update_disabled` (переадресация в DLL из кэша и её
выключение), `harness_server` (сценарий ККТ и проверка обновления на живом сервере).
Стенд работает со своим пустым кэшем обновлений и настоящий не трогает.

SDK Native API 1С (VNCOMPS) в репозиторий не входит — его распространяет 1С. Каталог `include` с его
заголовками — переменная окружения `ONEC_SDK` или `-DONEC_SDK=…`; в CI он берётся из секрета репозитория.

**Пакет для БПО** — `dist\EmulkonDriver_<версия>.zip`:

- `INFO.XML` — `progid="AddIn.EmulkonDriver"`, типы «ККТ,ЭквайринговыйТерминал,ЭлектронныеВесы,ВесыСПечатьюЭтикеток,ПринтерЧеков,ПринтерЭтикеток,СканерШтрихкода,СчитывательМагнитныхКарт,ДисплейПокупателя,ТерминалСбораДанных,СчитывательRFID,УстройствоРаспознавания» (все 12 типов), имя
  «ЭМУЛЯТОР Эмулкон <версия> (imiron.ru)». Разработчик — в имени и в описании драйвера: отдельного
  поля для него в требованиях нет. В справочнике БПО имя остаётся от загруженного архива, а версию
  работающей DLL показывает форма настройки экземпляра — после самообновления они расходятся;
- `MANIFEST.XML`;
- `EmulkonDriver_<версия>_win64.dll` и `…_win32.dll`, точки версии заменены на «_»
  (`EmulkonDriver_0_6_1_win64.dll`). Версия в имени обязательна: тонкий клиент помнит
  установленные компоненты по имени файла (`%APPDATA%\1C\1cv8\ExtCompT\registry.xml`) и DLL
  с прежним именем не переустанавливает — после «Обновить драйвер» касса осталась бы на старой версии.

С драйвером Linux (`build.ps1 -LinuxDriver <.so>`, в CI — всегда) в пакете ещё
`libEmulkonDriver_<версия>_lin64.so`, в `MANIFEST.XML` — строка с `os="Linux"`.

## Сборка (Linux)

Та же кодовая база: платформенный слой — `platform.h` (`platform_win.cpp` / `platform_posix.cpp`),
HTTP — WinHTTP на Windows и свой клиент HTTP/1.1 на сокетах на Linux (`http_posix.cpp`: Content-Length,
chunked, таймауты, поток событий с отменой). Внешних библиотек нет: `libstdc++` и `libgcc` слинкованы
статически, наружу видны только экспорты Native API (`version.script`).

```bash
cmake -S component -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DONEC_SDK=<каталог include SDK>
cmake --build build && ctest --test-dir build --output-on-failure
```

Нужны GCC 10+, CMake 3.20+ и `uuid/uuid.h` (его подключает `com.h` из SDK). CI собирает в
`manylinux_2_28` (glibc 2.28) — так библиотека работает на Astra 1.7, РЕД ОС, Альт, Ubuntu 20.04 и
новее ([.github/scripts/linux-driver.sh](../.github/scripts/linux-driver.sh)). Тесты те же, что на
Windows; для `harness_server` нужен сервер (`EMULKON_TEST_SERVER`).

Самообновление на Linux: кэш `$XDG_CACHE_HOME/emulkon/driver/<версия>/` (по умолчанию
`~/.cache/emulkon/…`), сервер отдаёт `EmulkonDriver_<версия>_lin64.so` (`os=Linux` в проверке
обновления), переадресация экспортов — через `dlopen`.

БПО берёт имя класса из `progid` (часть после точки) и создаёт объект `AddIn.<символическое имя>.EmulkonDriver`.

## Подключение в 1С

0. Скачать ZIP со страницы загрузок сервера: `http://<сервер>:8737/downloads`.
1. В БПО: «Драйверы оборудования» → «Загрузить новый драйвер из файла» → выбрать ZIP.
2. «Подключаемое оборудование» → создать экземпляр нужного типа (ККТ, эквайринговый терминал, весы, принтер чеков или этикеток) с драйвером «ЭМУЛЯТОР Эмулкон <версия> (imiron.ru)».
3. Открыть «Настройка», указать адрес сервера, при необходимости — токен, и нажать **«ОК»**.
   Группа «Экземпляр (заполняет Эмулкон)»:
   - «Идентификатор экземпляра» форма заполняет новым GUID сама, а «ОК» его сохраняет. По нему
     каждый экземпляр — своё устройство на сервере: две ККТ одной базы не смешиваются. Пока
     экземпляр ни разу не настраивали, сервер считает устройство по рабочему месту и помечает
     «не настроено» (ARCHITECTURE §4.3);
   - «Наименование в 1С» и «База 1С» — для веб-интерфейса Эмулкона: так видно, чьё устройство.
     Пустую «Базу 1С» драйвер берёт из командной строки 1С (`/F`, `/S`, `/IBName`, `/IBConnectionString`).
   Копировать экземпляр с этими параметрами не нужно: копия получит пометку «копия».
4. «Тест устройства» должен ответить «Тест пройден. ЭМУЛЯТОР ККТ (Эмулкон) …».

**«Драйвер не сертифицирован или снят с поддержки».** БПО 3.2.9 дописывает это к тексту каждой
ошибки драйвера, который не поставляется в конфигурации (`МенеджерОборудования.АнализТекстаОшибкиОборудования`,
`ДрайверПоставляетсяВКонфигурации`). Так БПО помечает любой сторонний драйвер; признака, который
снял бы приписку, у внешней компоненты нет. Эмулятор под поставляемый драйвер не маскируется (§10):
сама ошибка — первая строка сообщения.

## Не сделано

- Linux x86 (32 бита) и ARM: собирается только x86_64. Проверка в настоящей 1С под Linux —
  [tests/linux](../tests/linux/README.md).
- Лог драйвера на рабочем месте. `LogIsEnabled="false"`: журнал обменов ведёт сервер.
