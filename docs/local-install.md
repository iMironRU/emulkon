# Локальная поставка: установка, служба, Панель управления, оснастка MMC

Проектный документ. Решения владельца — §1; остальное — предложение, открытые вопросы — §6.

Сделано: сервер — служба Windows, настройки из реестра, журнал событий (шаг 1); установщик на машину —
раскладка §2, служба, права, брандмауэр, перенос прежней установки (шаг 2); мастер обслуживания §3 (шаг 3,
setup/README.md); трей управляет службой (шаг 4, tray/README.md); версия 0.8.0; элемент Панели управления
(шаг 5); таблица «что где» (§5); оснастка MMC: каркас, «Служба», рабочие места, устройства, сценарии, журнал, обновления и перенос настроек (§4.1, этапы 1–5, console/README.md).

## 1. Решения владельца (2026-10-14)

1. **Облако отложено** — сначала доводим локальную поставку.
2. **Установщик как у «настоящих» приложений:** в «Установленных приложениях» — изменить, восстановить, удалить.
3. **Установка требует прав администратора; сервер — служба Windows.** Это отменяет прежнее решение
   «ставим в профиль пользователя без админа» (setup/README.md: манифест `asInvoker`).
4. **Элемент Панели управления** и **консоль управления — настоящая оснастка MMC** (`mmc.exe`, COM-DLL).
5. **Веб-интерфейс остаётся.** Что где делается (трей, веб, оснастка, Панель управления) и где допустимо
   дублирование — проговорить отдельно (§5).
6. **Порядок:** установщик → Панель управления → оснастка MMC.
7. **Служба — под `LocalService`**; каталог данных в `%ProgramData%\Emulkon` с правом записи для неё.
8. **Старая установка в профиле пользователя:** установщик находит её, переносит данные сервера в
   `%ProgramData%` и удаляет старую запись и файлы.
9. **Пользователи** (группа «Пользователи») могут запускать и останавливать службу `Emulkon` без UAC — из трея;
   менять параметры службы — только администраторы.

## 2. Где что лежит (решение владельца 2026-10-14)

Правило: **Program Files — только то, что ставит установщик** (во время работы туда не пишется, «Восстановить»
заменяет целиком); **ProgramData — состояние службы**; **профиль пользователя — только его**; **настройки — в
реестре**.

```
C:\Program Files\Emulkon\
├─ bin\        emulkon.exe (служба Emulkon), EmulkonTray.exe, EmulkonSetup.exe (обслуживание)
├─ console\    оснастка MMC: EmulkonSnapIn.dll, Emulkon.msc
├─ 1C\         для 1С; открывает ярлык «Загрузки для 1С», раздаёт страница /downloads
│  ├─ driver\  EmulkonDriver_<версия>.zip («Драйверы оборудования»), DLL x86/x64 для самообновления
│  └─ epf\     обработки для 1С (помощник настройки — бэклог)
├─ setup\      EmulkonSetup_<версия>.exe — поставить Эмулкон на соседний компьютер (тоже на /downloads)
└─ docs\       README, лицензия, сведения о сторонних компонентах

C:\ProgramData\Emulkon\        запись — служба (LocalService) и администраторы; пользователи — чтение
├─ data\       registry.json (устройства, рабочие места, хеши токенов мест), scenarios.json, journal\
├─ logs\       service.log — старт, остановка, ошибки службы (старт и сбои — ещё и в журнал событий Windows)
└─ backup\     копии data\ и настроек перед обновлением и при переносе старой установки

%LOCALAPPDATA%\Emulkon\        у каждого пользователя
├─ driver\<версия>\            кэш самообновления драйвера: его грузит 1С этого пользователя. Общий кэш на машину с
│                              записью для всех не делаем — туда можно подложить DLL
└─ logs\tray.log
```

- **Веб-интерфейс** встроен в `emulkon.exe` (go:embed), отдельной папки нет: версия всегда совпадает с сервером,
  подменить файлы нельзя, «Восстановить» чинит его вместе с сервером.
- **Меню «Пуск» → «Эмулкон»** (общее): консоль, трей, веб-интерфейс, «Загрузки для 1С» (папка `1C\`), «Проверка
  работы». Ярлыка удаления нет — это «Установленные приложения».
- **Служба `Emulkon`** — «Эмулкон — сервер эмуляции оборудования», автозапуск, перезапуск при сбое.
- **`HKLM\…\Uninstall\Emulkon`** — запись в «Установленных приложениях» для всех пользователей;
  **`HKLM\…\Run` → `EmulkonTray`** — автозапуск трея у каждого пользователя (флажок).

### 2.1. Настройки — в реестре (решение владельца 2026-10-14)

```
HKLM\SOFTWARE\Emulkon\            InstallDir, Version
HKLM\SOFTWARE\Emulkon\Server\     Addr, Network, DataDir, LogLevel, ControlTokenHash, DeviceTokenHash,
                                  UpdateMode, UpdateChannel
                                  права: администраторы — запись, LocalService — чтение, пользователи — нет
HKLM\SOFTWARE\Policies\Emulkon\   те же значения из групповой политики — перекрывают обычные
HKCU\Software\Emulkon\Tray\       настройки трея (вместо %APPDATA%\Emulkon\tray.ini)
```

- Сервер кроссплатформенный (Docker, CI): порядок — ключи командной строки → переменные окружения → реестр
  (только Windows) → значения по умолчанию. Файла настроек в ProgramData нет.
- **Токены Control и Device API — только хешами** (как токены рабочих мест): сам токен показывается один раз при
  выдаче (мастер «Изменить», оснастка).
- Перенос настроек между машинами — экспорт и импорт в оснастке.

### 2.2. Служба, права, брандмауэр, журнал событий

- **Режим службы** — `emulkon.exe -service` (так регистрирует установщик): SCM через advapi32 без внешних
  зависимостей; «работает» сообщается, когда порт уже слушается (занятый порт — ошибка старта, а не «запущено»).
  Каталог данных по умолчанию — `%ProgramData%\Emulkon\data`, лог — `%ProgramData%\Emulkon\logs\service.log`
  (больше 10 МБ — в `service.log.1`). Вне SCM ключ `-service` — ошибка с объяснением.
- **Журнал событий Windows** (решение владельца 2026-10-14): источник `Emulkon` в журнале «Приложение».
  Пишем: 1 — запуск, 2 — остановка, 3 — сбой (запуск, работа), 4 — сервер слушает сеть без токенов; позже —
  обновления (найдено, установлено, ошибка) и смена режима сети и токенов. Обмены с устройствами — нет (у них
  свой журнал). Текст событий виден, когда установщик зарегистрировал источник: `HKLM\SYSTEM\CurrentControlSet\
  Services\EventLog\Application\Emulkon`, `EventMessageFile` — `%SystemRoot%\Microsoft.NET\Framework64\v4.0.30319\
  EventLogMessages.dll` (часть Windows: сообщение любого кода — «%1»), своего файла сообщений не собираем.

- **Служба** запускает сервер (`emulkon.exe` в режиме службы: SCM, остановка по сигналу службы, лог в
  журнал событий Windows для старта и сбоев). Трей больше не поднимает сервер сам — показывает состояние
  службы и открывает веб и консоль.
- **Управление службой без прав:** установщик даёт группе «Пользователи» право запускать и останавливать
  службу `Emulkon` (дескриптор безопасности службы), чтобы трей мог «Перезапустить сервер» без UAC.
  — предложение, §6.
- **Брандмауэр:** правило для режима «сервер для касс в сети» ставит установщик (права уже есть).
- **Манифест установщика** — `requireAdministrator`.

### 2.3. Обновления (решения владельца 2026-10-14)

- **Источник — выпуски (releases) репозитория** на GitHub: установщик `EmulkonSetup_<версия>.exe` и описание
  версии (`latest.json`: версия, канал, ссылка, SHA-256, что нового). Каналы «стабильный» и «тестовый» —
  обычные и предварительные выпуски.
- **Без подписи кода** (сертификат платный — пока нет): целостность — SHA-256 из `latest.json`, загрузка только по
  HTTPS. Windows SmartScreen будет предупреждать о неизвестном издателе — написать в README.
- **Режим по умолчанию — «только уведомлять».** `UpdateMode`: выключено / уведомлять / ставить сразу.
- **Проверка** — служба раз в сутки; о новой версии сообщают трей, оснастка и веб-интерфейс.
- **Установка** — служба только сообщает; установщик качает трей или оснастка по кнопке «Обновить» — в «Загрузки»
  пользователя с меткой «из Интернета», со сверкой SHA-256, — и запускает мастер (UAC). Не служба и не `ProgramData`
  (#20): exe, тихо скачанный в общий каталог и запущенный оттуда, Defender счёл уклонением от защиты. Автоматическая установка без человека —
  позже, заданием планировщика от SYSTEM.
- **Установщик в режиме обновления:** копия `data\` и настроек в `backup\` → остановка службы → замена Program
  Files → запуск службы → проверка работы; при ошибке — откат на прежнюю версию.
- **Драйверы в базах 1С** перезагружать не нужно: при подключении они сами подтягивают DLL новой версии
  (самообновление, `%LOCALAPPDATA%\Emulkon\driver\<версия>`); архив в `1C\driver\` — для новых баз.

**Сделано** (консоль — 0.9.0, остальное — issue #8):

- Сервер (`server/internal/updates`) раз в сутки (первый раз — через минуту после запуска) читает `latest.json`
  (`UpdateURL` / `EMULKON_UPDATE_URL`, по умолчанию — последний выпуск GitHub); `UpdateMode` / `EMULKON_UPDATE_MODE`:
  `off` | `notify` (по умолчанию) и только сообщает — установщик не качает (#20). Состояние — `data/updates.json` и `GET /api/v1/updates`; проверка вручную —
  `POST /control/v1/updates/check`; журнал — `update.check`, `update.available` (один раз на версию).
- Трей раз в 10 минут (первый раз — через 30 с) спрашивает `GET /api/v1/updates`: уведомление один раз на версию (настройка `UpdateNotified`) и
  пункт «Обновить до X…» — трей фоном качает `EmulkonSetup_<версия>.exe` в «Загрузки» пользователя с меткой «из
  Интернета» (Zone.Identifier), файл остаётся, только если сошлись размер и SHA-256 из описания выпуска, и запускает
  мастер обновления (UAC). Адрес — только выпуск GitHub (`github.com/iMironRU/emulkon/releases/download/v<версия>/`);
  свой (`UpdateURL`) — только от сервера этого компьютера; иначе — страница выпуска.
- Веб-интерфейс — плашка «Вышла версия X» со ссылкой «Что нового».
- Консоль — «Проверить обновления…» (сама скачивает и запускает мастер); выгрузка настроек переносит `UpdateMode` и
  `UpdateURL`.

Ещё нет: «ставить сразу» (задание планировщика от SYSTEM), тестовый канал (предварительные выпуски), резервная копия и
откат в установщике при обновлении.

## 3. Мастер обслуживания

В «Установленных приложениях» у не-MSI программ кнопка «Восстановить» отдельно не показывается, поэтому так же,
как Office и Visual Studio:

- **«Изменить»** (`ModifyPath` → `EmulkonSetup.exe /maintain`) открывает мастер с тремя вариантами:
  - **Изменить** — те же параметры, что при установке: автозапуск трея, сервер для касс в сети (адрес,
    брандмауэр, токены), ярлыки;
  - **Восстановить** — файлы из установщика заново, служба, ярлыки, записи реестра, правило брандмауэра,
    затем проверка работы; данные и настройки не трогаются;
  - **Удалить** — как сейчас, флажок «удалить и данные».
- **«Удалить»** (`UninstallString`) — сразу удаление.
- Ключи для автоматизации: `/modify`, `/repair`, `/uninstall`, вместе с `/quiet`, `/log`.
- Мастер обслуживания запускается из копии установщика в `%ProgramFiles%\Emulkon\`; для восстановления файлов
  она несёт полный набор (как сейчас — ресурсы RCDATA).

## 4. Панель управления и оснастка MMC

- **Элемент Панели управления** «Эмулкон» (категории «Оборудование и звук», «Программы»; сделано в 0.8.0):
  командный объект `{57A099B6-A55F-4338-89B9-64CF1BED2518}` в `HKLM\…\ControlPanel\NameSpace` и
  `HKLM\SOFTWARE\Classes\CLSID`, без DLL. Открывает консоль `mmc.exe "<каталог>\console\Emulkon.msc"`; если
  консоль не создалась — веб-интерфейс. Позже — возможно, полноценный апплет со сведениями о службе.
- **Оснастка MMC** «Эмулкон»: дерево — сервер → рабочие места → устройства; сценарии; журнал; токены;
  загрузки. Список справа, панель действий. Данные — через Control API службы (тот же, что у веба).
  Готовый файл консоли `Emulkon.msc` в меню «Пуск».

### 4.1. Оснастка: этапы

1. **Каркас** (сделано, 0.8.0): `console\EmulkonSnapIn.dll` (C++, COM без ATL). Корень «Эмулкон» — сводка:
   служба, версии сервера и консоли, адрес, веб-интерфейс, режимы доступа, число устройств и рабочих мест;
   «Обновить». Разделы Служба, Рабочие места, Устройства, Сценарии, Журнал — пока окно-заготовка со ссылкой
   на веб-интерфейс. «О программе». Установщик регистрирует DLL (`DllRegisterServer`: COM-класс, ключи
   `HKLM\SOFTWARE\Microsoft\MMC\SnapIns` и `NodeTypes`), пишет `Emulkon.msc`, ярлык «Эмулкон — консоль».
2. **Служба** (сделано, 0.8.0): список — состояние, тип запуска, учётная запись, команда, адрес, кассы в сети,
   токены, где данные и журнал. «Действие»: запустить, остановить, перезапустить; выдать и снять токены
   управления и устройств; токен управления для консоли; открыть веб-интерфейс. «Свойства» — то же на одной
   странице плюс флажок «Сервер для касс в сети».
   - Токен — `emk_` + 32 случайных байта (base64url); показывается один раз с кнопкой «Копировать», в
     `HKLM\Software\Emulkon\Server` пишется только SHA-256 (`ControlTokenHash`, `DeviceTokenHash`), затем
     служба перезапускается — токены она читает при запуске.
   - Токен управления консоль держит в памяти до закрытия: выданный в ней — сразу, чужой — «Токен управления
     для консоли…». Без него при заданном токене сводка пишет «нужен токен управления».
   - «Кассы в сети» консоль не меняет сама: запускает `EmulkonSetup.exe /modify /network|/nonetwork /quiet`
     (§3) — тот же код меняет `Network`, правило брандмауэра и перезапускает службу.
   - Писать настройки службы может только администратор: консоль, открытая без прав, показывает
     «видно администратору», пункты выдачи токенов недоступны.
3. **Рабочие места и устройства** (сделано, 0.8.0) — списки из Control API (docs/protocol.md §2.3).
   - Рабочие места: подпись или код, базы 1С, устройства, сессии, токен (последние символы), последнее
     подключение. «Действие»: выдать и отозвать токен рабочего места (показывается один раз), «Новое рабочее
     место…» — завести заранее и сразу выдать токен. «Свойства»: подпись, заметка, токен, базы, принтеры,
     устройства.
   - Устройства: подпись или имя, код, класс, рабочее место, на связи, команды, активность. «Действие»:
     сбросить настройки к настройкам класса, удалить (драйвер заведёт заново). «Свойства»: подпись, заметка,
     сведения; вкладка «Состояние» — состояние модели и настройки на момент открытия, только чтение.
   - Менять состояние моделей, классы, действия устройств — в веб-интерфейсе (§5): «Открыть в веб-интерфейсе»
     ведёт на нужную вкладку.
4. **Сценарии и журнал** (сделано, 0.8.0).
   - Сценарии: правило, код, включено, условие и действие словами («класс kkt, метод PrintCheck, на 3-м
     вызове» → «ошибка 3: Нет бумаги»), ограничение, сработало из подходящих. «Действие»: включить и
     выключить, удалить; у раздела — «Выгрузить сценарии…» (JSON `{"rules":[…]}` без счётчиков) и «Загрузить
     сценарии…» (с тем же кодом — заменить, новые — добавить, остальные остаются). «Свойства» — правило
     целиком, только чтение. Создавать и править правила — в веб-интерфейсе (§5).
   - Журнал: последние 500 записей, новые сверху: №, время, направление, рабочее место, устройство, метод,
     задержка, сработавшие правила, начало данных. «Отбор…» — поиск по тексту записи (в памяти консоли),
     «Сбросить отбор»; «Выгрузить журнал…» — все записи по отбору в JSON Lines, потоком в файл. Строка
     состояния MMC — сколько записей и есть ли более ранние. «Свойства» — запись целиком. Поток вживую — в
     веб-интерфейсе.
5. **Обновления, выгрузка и загрузка настроек** (сделано, 0.9.0).
   - «Проверить обновления…» у корня: `latest.json` последнего выпуска
     (`github.com/iMironRU/emulkon/releases/latest/download/latest.json`: версия, дата, ссылка на установщик,
     SHA-256, размер, «что нового» из CHANGELOG; публикует `release.yml`). Новее установленной — окно «что нового»
     и «Скачать и установить»: установщик — только по https и с именем `EmulkonSetup_<версия>.exe`, в
     «Загрузки» пользователя с меткой «из Интернета» (до #20 — `ProgramData\Emulkon\updates\`), файл пишется, только если сошлись размер и SHA-256; затем мастер обновления.
     Выпуски до 0.9.0 описания не публиковали — консоль так и пишет.
   - У «Службы» — «Выгрузить настройки…» и «Загрузить настройки…»: значения `HKLM\Software\Emulkon\Server`
     (Addr, Network, DataDir, DownloadsDir, LogLevel, хеши токенов) в JSON `{"format":"emulkon-settings",
     "version":1,…,"server":{…}}`. Токенов в файле нет — только SHA-256: на другом компьютере подходят те же токены.
     Загрузка делает ключ как в файле (чего нет в файле — по умолчанию), проверяет значения, перезапускает
     работающую службу; «Кассы в сети» меняет мастер «Изменить» — вместе с правилом брандмауэра.
   - Ещё не сделано из §2.3: проверка службой раз в сутки, уведомление в трее и баннер в веб-интерфейсе,
     `UpdateMode`, тестовый канал.

Консоль `Emulkon.msc` — XML MMC 3.0, пишется установщиком текстом: единственный корень — узел оснастки,
режим пользователя с одним окном (как `services.msc`: без вопроса о сохранении). Автоматизация
`MMC20.Application` (`Document.SnapIns.Add`) на Windows 11 падает на любой оснастке, даже встроенной «Папке»,
— поэтому не она. Консоль запрашивает права администратора (так устроен `mmc.exe`); сводка читает
настройки службы из `HKLM\Software\Emulkon\Server`, обычному пользователю они закрыты — адрес тогда по
умолчанию.

## 5. Что где (решение владельца 2026-10-15; по опыту эксплуатации может меняться)

Оснастка — администратору компьютера (служба, доступ, обновления, обзор), веб — тестировщику (работа с
устройствами, сценарии, журнал вживую), трей — то, что нужно у кассы сейчас. Панель управления открывает оснастку.

| Что | Трей | Веб-интерфейс | Оснастка MMC |
|---|---|---|---|
| Состояние службы, запуск, остановка | ✓ | — | ✓ |
| Параметры службы: адрес, кассы в сети, токены Control/Device API (выдача, показ один раз) | — | — | ✓ |
| Рабочие места, токены рабочих мест | — | ✓ | ✓ |
| Устройства: список, сброс, удаление | — | ✓ | ✓ |
| Устройства: действия (скан, карта, вес), экраны, лента чеков | экраны, чеки | ✓ | — |
| Сценарии сбоев: включить, выключить | — | ✓ | ✓ |
| Сценарии сбоев: правка правил | — | ✓ | — |
| Журнал обменов: вживую, фильтры | — | ✓ | — |
| Журнал обменов: просмотр, экспорт в файл | — | ✓ | ✓ |
| Обновления: проверить, скачать, установить | уведомление, «Обновить» | баннер | ✓ |
| Экспорт и импорт настроек | — | — | ✓ |

Дублируются оснастка и веб: рабочие места, устройства, журнал.

## 6. Открытые вопросы

Закрыты решениями §1.7–§1.9, §2 и §5: учётная запись службы, переход со старой установки, право пользователей
управлять службой, раскладка папок, настройки в реестре, обновления, что где.

1. **Репозиторий на GitHub:** у локального репозитория пока нет удалённого. Выпуски закрытого репозитория
   без токена не скачать — для обновлений репозиторий (или отдельный репозиторий выпусков) должен быть
   открытым.
2. **Несколько пользователей на одной машине** (терминальный сервер): одна служба и один сервер на всех —
   рабочие места различаются, как сейчас, по `WorkstationID`.
