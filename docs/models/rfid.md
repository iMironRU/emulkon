# Модель считывателя RFID (эмулятор)

Код — `server/internal/models/rfid`. Контракт — [rfid.md](../bpo-requirements/rfid.md).

**Исходное состояние:** поле антенны пусто, сессии нет.

Метки «кладут в поле» в панели управления: действие `add_tag` `{"tid", "epc", "user"}` — пустые
поля генерируются (TID `E280…`, 96 бит; EPC `30…` — SGTIN-96); `remove_tag` `{"tid"}`;
`clear_field`. HEX без учёта регистра, хранится в верхнем.

| Метод | Что делает |
|---|---|
| OpenSessionRFID | открывает сессию; метки, уже лежащие в поле, уходят первым пакетом |
| CloseSessionRFID | закрывает сессию (и `DisconnectEquipment`) |
| GetDataTagsRFID | `<Table><Tag TID EPC USER/></Table>` пакета; отмечает его доставленным |
| SaveDataTagRFID | при открытой сессии пишет данные (HEX) в банк EPC (1) или USER (2) метки с этим TID и EPC (пустой EPC — любая с этим TID); возвращает TID и EPC метки |

**Пакеты и события.** При открытой сессии каждая метка, о которой в этой сессии ещё не
сообщали, попадает в новый пакет `pkg-N`, и в 1С уходит событие `RFID` с идентификатором пакета.
Убранная из поля метка, вернувшись, считается новой. Хранятся последние 50 пакетов.

| Код | Текст | Когда |
|---|---|---|
| 75 | Сессия RFID не открыта | запись без сессии |
| 76 | Метки нет в поле считывателя | запись в отсутствующую метку |
| 77 | Пакета с данными меток нет | неизвестный идентификатор пакета |
| 98, 99 | | банк не 1 и не 2, данные не HEX |

В состоянии: `session`, `field`, `packages` (последние 10: метки, доставлен ли), `writes`.
