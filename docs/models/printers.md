# Модели принтеров (эмулятор)

Код — `server/internal/models/printers`: принтер чеков (`receipt_printer`) и принтер этикеток
(`label_printer`). Контракт — [printers.md](../bpo-requirements/printers.md).

Общее для обоих: перед печатью проверяются бумага (90) и крышка (91); напечатанное попадает на
ленту устройства (`device.print`) — её видно в карточке устройства и во всплывающих окнах трея.
Каждый документ помечен как эмуляторный.

| Код | Текст | Когда |
|---|---|---|
| 90 | Нет бумаги | `paper: false` (у принтера этикеток — кончились этикетки) |
| 91 | Крышка принтера открыта | `cover_open: true` |
| 92 | Тип штрихкода не поддерживается | тип не из списка требований или `barcodes: false` |
| 93 | Неверный статус пакета | не `first`, `regular`, `last` |
| 94 | Нет разметки этикетки | пакет без `Formatting`, а задание печати не начато |
| 98, 99 | неверные параметры, не поддерживается | |

Типы штрихкода — объединение списков 3.6 и 3.7 (`QR` и `QRCode` — одно и то же), без учёта
регистра.

## Принтер чеков

**Исходное состояние:** бумага есть, крышка закрыта, ширина строки 42, штрихкоды печатает.

| Метод | Что делает |
|---|---|
| PrintTextDocument | печатает документ: строки `TextString` (длинные переносятся по ширине) и штрихкоды `[EAN13: …]` по центру. Значение штрихкода — `ValueBase64`, для старых ревизий `Value` или `Barcode` |
| OpenCashDrawer | открывает денежный ящик: `drawer_open`, счётчик и время в состоянии |
| GetLineLength | ширина строки (`line_length`) |

Документ — вид `text` («Текстовый документ»), сверху и снизу пометка
«*** ЭМУЛЯТОР · НЕ ФИСКАЛЬНЫЙ ***».

| Ключ `PUT …/state` | Значение | |
|---|---|---|
| `paper` | bool | бумага есть |
| `cover_open` | bool | крышка открыта |
| `line_length` | 24–80 | ширина строки в символах |
| `barcodes` | bool | принтер печатает штрихкоды; `false` — любой штрихкод даёт 92 |
| `drawer_open` | bool | денежный ящик открыт (закрыть — `false`) |
| `drawer_auto_close_s` | 0–600, `10` | ящик закрывается сам; 0 — пока не закроют |

В состоянии: `documents` (напечатано), `drawer_opens`, `drawer_opened_at`.

## Принтер этикеток

**Исходное состояние:** этикетки есть, крышка закрыта, задания нет.

| Метод | Что делает |
|---|---|
| InitializePrinter | отмечает инициализацию (`initialized`, счётчик); печать без неё тоже работает — БПО её не требует |
| PrintLabels | печатает пакет этикеток (ниже) |

**Задание печати.** Пакет с `Formatting` начинает новое задание: разметка запоминается. Пакет без
`Formatting` продолжает открытое задание с его разметкой — так обрабатывается и второй пакет
БПО со статусом `first`. `last` закрывает задание; пакет без разметки при закрытом задании — 94.
Каждый пакет печатается сразу, одним документом на ленте (вид `label`):
- заголовок «*** ЭМУЛЯТОР · ЭТИКЕТКИ ***», размер этикетки, число этикеток и копий;
- по каждой этикетке — номер, `× Quantity`, поля по порядку на этикетке (сверху вниз, слева
  направо): `Имя: значение`, штрихкод `[EAN13: …]`, картинка `[картинка, N КБ]`. `UserData` не
  печатается.

Значение поля: `Record` этикетки, иначе `Value` шаблона; у `Static="true"` — всегда из шаблона.
Штрихкод — `ValueBase64` или `Value`. `Record` с полем, которого нет в разметке, — 98.

Для веб-интерфейса документ несёт разметку `layout`: размер, поля шаблона (координаты в мм,
шрифт, выравнивание, тип штрихкода) и значения первых 20 этикеток пакета. Картинки больше 64 КБ
в `layout` не попадают.

| Ключ `PUT …/state` | Значение | |
|---|---|---|
| `paper` | bool | этикетки есть |
| `cover_open` | bool | крышка открыта |

В состоянии: `initialized`, `job` — текущее или последнее задание (статус последнего пакета,
пакетов, этикеток, копий, размер этикетки, открыто ли), `jobs`, `labels_printed` (копий всего).

## Старая схема (БПО УТ 10.3)

Принтер чеков печатает текст по строкам: `ОткрытьЧек(ИД, Фискальный, Возврат, —, НомерЧека out, НомерСмены out)`,
`НапечататьНефискСтроку(ИД, Текст)`, `НапечататьФискСтроку(ИД, Наименование, Количество, Цена, Сумма, Секция, НДС)`,
`НапечататьШтрихКод(ИД, Тип, Штрихкод)`, `ЗакрытьЧек(ИД, Наличные, Безнал1, Безнал2, Безнал3)`, `ОтменитьЧек(ИД)`.
Собранное печатается одним документом, как `PrintTextDocument` (`legacy.go`); номер смены — 0.
Строка без открытого чека и второй `ОткрытьЧек` — ошибка 95 «Неверное состояние чека».

Прогон в УТ 10.3.88.3 показал: для типа «ПринтерЧеков» её БПО печатает текст документом
(`НапечататьТекстовыйДокумент`), а строки `ОткрытьЧек`…`ЗакрытьЧек` шлёт только типу «ФискальныйРегистратор»
(`ПечатьТекста`, `ПечатьЧекаПоШаблону`). Методы оставлены: их проверяет стенд драйвера, а в других
конфигурациях со старой БПО порядок вызовов может отличаться.
