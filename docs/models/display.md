# Модель дисплея покупателя (эмулятор)

Код — `server/internal/models/display`. Контракт — [display.md](../bpo-requirements/display.md).

**Исходное состояние:** 20 символов × 2 строки; умеет текст, QR, HTML, статус операции и статус
рабочего места; графики и сенсорного экрана нет; экран пуст.

| Метод | Что делает |
|---|---|
| GetCustomerDisplayOptions | параметры из состояния (все атрибуты, bool — `true`/`false`) |
| StringOutputOnCustomerDisplay | строки по переводам строк: лишние строки отбрасываются, длинные обрезаются по ширине, пустая строку не меняет. HTML с экрана уходит, QR остаётся рядом |
| ClearCustomerDisplay | экран пуст: строки, QR, HTML |
| QRCodeOutputOnCustomerDisplay | QR: значение обязательно, картинка — PNG в Base64 (до 2 МБ) или пусто |
| OutputHTML | HTML на экран (до 4 МБ) |
| AddMediaFile | файл в хранилище дисплея по имени (без пути, Base64, всего до 32 МБ) |
| DisplayOperationStatus | индикатор: 0–2 |
| DisplayWorkplaceStatus | статус рабочего места 0–4; звуковой сигнал считается |

| Код | Текст | Когда |
|---|---|---|
| 85 | Дисплей не поддерживает этот вывод | выключена нужная возможность (`text`, `qr`, `html`, `status`, `workplace_status`; медиафайлы — при `html`) |
| 86 | Дисплей покупателя не отвечает | `broken: true` |
| 98, 99 | неверные параметры, не поддерживается | |

**Экран в панели управления.** Строки — табло с моноширинным шрифтом, QR — картинкой и текстом,
индикаторы статусов. **HTML показывается только в `<iframe sandbox>` без скриптов** — чужой HTML
не попадает в страницу панели; медиафайлы подставляются в `src` как `data:` (действие `media`).

**Сенсорный экран** (`interactive: true`): действие `click` `{"element": "…"}` — событие `OnClick`
с именем элемента. Без `interactive` действие отклоняется: БПО такие события не слушает.

| Ключ `PUT …/state` | Значение |
|---|---|
| `columns` | 8–80 |
| `rows` | 1–20 (размер меняет — экран очищается) |
| `text`, `graphics`, `qr`, `html`, `status`, `workplace_status`, `interactive` | bool — что умеет дисплей |
| `broken` | bool — дисплей не отвечает |

В состоянии: `lines`, `qr_view`, `html_view`, `shown` (что на экране: text, qr, html, clear),
`operation_status`, `workplace`, `beeps`, `media` (имя, размер), `outputs`, `clicks`.

## Старая схема (БПО УТ 10.3)

`ПолучитьПараметрыВывода(ИД, Столбцов out, Строк out)` — размер экрана (20×2). Остальные методы
(`ВывестиСтрокуНаДисплейПокупателя`, `ОчиститьДисплейПокупателя`) в старой и новой схеме одинаковы.
