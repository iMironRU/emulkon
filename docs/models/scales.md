# Модели весов (эмулятор)

Код — `server/internal/models/scales` (электронные весы) и `server/internal/models/labelscales`
(весы с печатью этикеток). Контракт — [scales.md](../bpo-requirements/scales.md).

## Электронные весы

**Исходное состояние:** платформа пуста (0 кг), тары нет, вес стабилен, предел 15 кг, вес
кладут на экране весов (`weight_mode=manual`).

Вес «кладут» на экране весов — в карточке устройства веб-интерфейса — или ключом `weight`.
Весы показывают нетто = брутто − тара.

| Метод | Что делает |
|---|---|
| ScaleOptions | `<ScaleOptions Calibrate="true" WeighingEvent="false" AdvancedData="true" PlacementControl="false"/>` |
| GetWeight | нетто, кг. Проверки: не больше предела (70), стабилен (71), без ошибки размещения (72). При `weight_mode=ask` — запрос на экране весов (ниже) |
| Calibrate | тара: `TareWeight=0` — текущий брутто, иначе заданный вес; не больше предела (70) |
| GetData | `<Data Weight Stable PlacementError IntersectionZones/>` — без проверок, как есть |

**`weight_mode=ask` — вес на каждое взвешивание.** `GetWeight` открывает на экране весов запрос
«ВЗВЕШИВАНИЕ» с полем «Вес, кг» и кнопками «Взвесить» и «Отмена». Механизм тот же, что у
терминала: `device.prompt`, `POST …/prompt` с `{"value": 0.532}`, `device.prompt_done`. Окно
показывают трей и веб-интерфейс. Отмена — 73, никто не ответил за `prompt_timeout_s` — 74.

Событие «Взвешивание» (`ExternalEvent`) модель сама не шлёт и в `ScaleOptions` не объявляет.
Отправить его вручную можно через канал событий: `POST /control/v1/devices/{id}/events`
([protocol.md](../protocol.md) §1.4).

| Код | Текст | Когда |
|---|---|---|
| 70 | Перегрузка весов | вес или тара больше `max_weight` |
| 71 | Вес не стабилизирован | `stable: false` |
| 72 | Ошибка размещения товара на весах | `placement_error: true` |
| 73 | Взвешивание отменено | `cancel` на экране весов |
| 74 | Время ожидания веса истекло | в режиме `ask` никто не ответил |
| 98, 99 | неверные параметры, не поддерживается | |

| Ключ `PUT …/state` | Значение | |
|---|---|---|
| `weight` | кг ≥ 0 | брутто на платформе |
| `tare` | кг ≥ 0 | тара |
| `stable` | bool | вес стабилен |
| `placement_error` | bool | товар задевает край (`IntersectionZones` = `zones`) |
| `zones` | строка `err-1,err-2` | зоны пересечения |
| `max_weight` | кг > 0 | предел весов |
| `weight_mode` | `manual`, `ask` | откуда вес |
| `prompt_timeout_s` | 5–240 | ожидание в режиме `ask` |

## Весы с печатью этикеток (OFFLINE)

**Исходное состояние:** товаров нет, префикс весового штрихкода `21`.

| Метод | Что делает |
|---|---|
| UploadGoods | разбирает пакет и **дополняет** таблицу товаров по PLU: новый PLU добавляется, существующий заменяется. Статус пакета (`first`/`regular`/`last`) проверяется и попадает в статистику выгрузки. Пустой или неразборчивый пакет — 98 |
| ClearGoods | удаляет все товары и картинки |
| UploadProductImages | картинки PNG (Base64) по PLU; картинка товара, которого нет в таблице, всё равно хранится |

Этикетку печатает человек на весах: `POST /control/v1/devices/{id}/actions/print_label`
`{"plu": 1, "weight": 0.532}`, в веб-интерфейсе — кнопка у товара. Этикетка попадает на ленту
весов (`device.print`, вид `label`), её видно в карточке устройства и во всплывающем окне трея:
- наименование, цена за кг, вес, стоимость;
- дата упаковки и «годен до» (по `ShelfLife`), состав;
- **весовой штрихкод EAN-13**: префикс (2 цифры) + код товара (5) + вес в граммах (5) +
  контрольная цифра. Для штучного товара (`IsWeightGoods=false`) — вес единицы
  (`WeightPieceOfGoods`) или заданный.

| Ключ `PUT …/state` | Значение | |
|---|---|---|
| `barcode_prefix` | две цифры, `20`–`29` | префикс весового штрихкода |

| Код | Текст | Когда |
|---|---|---|
| 80 | Товар с таким PLU не загружен | печать этикетки |
| 81 | Неверный статус пакета | не `first`, `regular`, `last` |
| 98, 99 | | |

В состоянии устройства: `goods` (товары, по PLU, первые 500), `goods_count`, `images` (PLU с
картинками), `labels` (напечатано этикеток); `upload` и `images_upload` — последняя выгрузка
товаров и картинок: пакетов, записей, статус последнего пакета, время. Выгрузка начинается
заново с пакета `first` или с любого пакета после `last`.

Действие `image` `{"plu": 1}` отдаёт картинку товара (`png_base64`) — для веб-интерфейса.
Картинок эмулятор хранит не больше 32 МБ (одна — до 2 МБ в Base64), больше — 98.
