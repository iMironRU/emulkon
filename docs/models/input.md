# Модели устройств ввода (эмулятор)

Код — `server/internal/models/input`: сканер штрихкода (`scanner`) и считыватель магнитных карт
(`card_reader`). Контракт — [input-devices.md](../bpo-requirements/input-devices.md).

Своих методов нет: `ConnectEquipment`, `DisconnectEquipment`, `EquipmentTest` — успех, любой другой
метод — 99. Данные приходят в 1С **событиями** (docs/protocol.md §1.4): человек «сканирует» или
«проводит карту» в панели управления (`POST …/actions/{name}`), модель отдаёт событие, драйвер
поднимает в 1С `ExternalEvent`. Событие пишется в журнал (`direction: event`) с числом слушающих
драйверов: если драйвер не подключён, событие останется только в журнале.

| Код | Текст |
|---|---|
| 98 | Неверные параметры вызова |
| 99 | Метод не поддерживается: у устройства ввода нет методов |

## Сканер штрихкода

Действие `scan`: `{"barcode": "…"}` — свой код (до 4096 символов, разделитель GS — символ 29) или
`{"kind": "…"}` — сгенерировать:

| kind | Что |
|---|---|
| `ean13` | EAN-13 с префиксом 46 и верной контрольной цифрой |
| `ean8` | EAN-8 |
| `weight` | весовой EAN-13: префикс 21, код товара 5 цифр, вес в граммах 5 цифр |
| `datamatrix` | код маркировки: `01` GTIN-14, `21` серийный номер (13), GS, `93` код проверки (4) |
| `code128` | `EMUL-` и 6 цифр |
| `qr` | ссылка `https://imiron.ru/emulkon/q/…` |

Событие — `Barcode` с кодом как есть; при `event_format: base64` — `BarcodeBase64` с кодом в Base64.

## Клавиатурный режим (сканер и считыватель)

Многие кассы работают со сканером «как с клавиатурой» (USB HID): код просто вводится в активное
поле 1С, без драйвера. Эмулкон умеет и так:

| Ключ `PUT …/state` | Значение | |
|---|---|---|
| `input_mode` | `driver` (по умолчанию), `keyboard`, `both` | событием через драйвер, вводом с клавиатуры или обоими |
| `keyboard_suffix` | `enter`, `tab`, `none` | что нажать после кода; у сканера по умолчанию `enter`, у считывателя `none` — суффикс дорожки (13) уже Enter |
| `keyboard_delay_ms` | 0–10000, `1500` | пауза перед вводом: успеть переключиться в окно 1С |

В режиме `keyboard` и `both` действие `scan` или `swipe` пишет запись журнала
`device.keyboard` `{text, suffix, delay_ms}`; трей рабочего места ждёт паузу и вводит текст в
активное окно (SendInput: символы Unicode, CR и LF — Enter, TAB — Tab). В режиме `keyboard`
события в 1С нет. В окно, запущенное от администратора, Windows ввод не пропускает — трей пишет
это в свой лог.

## Библиотеки тестовых данных

Свои штрихкоды, коды маркировки и карты с подписями — кнопки в карточке устройства. Ключ `library` — настройка устройства: хранится в
реестре и задаётся классу по умолчанию (не больше 50 записей, подпись — 1–60 символов, без повторов):

| Устройство | Запись | Действие |
|---|---|---|
| сканер | `{title, barcode}` | кнопка — `scan` с этим кодом |
| считыватель | `{title, track1, track2, track3}` (хотя бы одна дорожка) | `swipe` `{"card": "<подпись>"}` |

## Считыватель магнитных карт

Действие `swipe`: `{"card": "discount" | "employee"}` — тестовые дисконтная карта и карта кассира
(не банковские), или `{"track1", "track2", "track3"}` — свои данные дорожек.

Данные события собираются по настройке дорожек: для каждой включённой дорожки с данными — префикс
(если не 0), данные, суффикс (если не 0). По умолчанию — как в настройке считывателя БПО: только
дорожка 2 с суффиксом 13 (CR), поэтому дисконтная карта даёт `7770000000017=2912\r`. Ни одной
включённой дорожки с данными — ошибка действия.

Событие — `TracksData`; при `event_format: base64` — `TracksDataBase64`.

| Ключ `PUT …/state` | Значение | |
|---|---|---|
| `event_format` | `plain`, `base64` | оба устройства |
| `tracks` | `[{use, prefix, suffix}] × 3`, коды 0–255 | считыватель |

В состоянии: `scans` / `swipes` — сколько раз, `last` — последние 20 (новые первыми).
