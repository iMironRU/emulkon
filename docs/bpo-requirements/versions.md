# Версии стандарта драйверов и версии БПО

Выжимка из таблицы «Изменения в стандарте» документа «Требования к разработке драйверов
подключаемого оборудования. Версия 5.0» (ИТС, metod8dev, документ 6038, опубликован 18.11.2025;
нужна авторизация ИТС). Текст требований не копируем — только что менялось и где.
Архив версий до 4.8 на ИТС по ссылке из документа сейчас недоступен (404).

## Что это значит для Эмулкона

- Драйвер объявляет ревизию **4008** и реализует схему подключения 4.3+ (`ConnectEquipment`).
  БПО, которые знают только старую схему (параметры по одному, `SetParameter` + `Open`), к нему
  не подключатся. Для них нужен документ требований до 4.3 — на ИТС его сейчас нет.
- Эквайринг: БПО 3.2.9 вызывает `Pay` (4.3+), а не `AuthorizeSales` (прогон tests/1c, журнал).
- **5.0** (ТС ПИоТ у ККТ) — **поддержано с 0.7.4**: четыре метода Piot* и признак `piot`. БПО 3.3
  включает ПИоТ по `SupportFNPiot` и настройке экземпляра, а не по ревизии драйвера (4008).

## Старая схема подключения (УТ 10.3) — поддержка по этапам

Источник — код БПО УТ 10.3.88.3 (`ПодключаемоеОборудованиеУниверсальныйДрайверКлиент`): документа до 4.3 на ИТС нет.

1. **Подключение (0.7.5).** `УстановитьПараметр` (SetParameter) копит параметры, в том числе`EquipmentType`;
   `Подключить` (Open, 0 DeviceID out) и `ТестУстройства` (DeviceTest, 0 описание out, 1 демо out) собирают
   из них ConnectionParameters и идут тем же путём, что `ConnectEquipment` / `EquipmentTest`; `Отключить` (Close) =
   `DisconnectEquipment`; `ПолучитьПараметры` (GetParameters) — та же таблица, что `EquipmentParameters`.
   `ПолучитьНомерВерсии` нет намеренно: без него БПО берёт версию и описание из нового `ПолучитьОписание`.
   Методы ККТ в УТ 10.3 — те же, что в 4.x (ревизия ≥ 3000), сканер и считыватель — событиями.
2. **Эквайринг (0.7.5).** Шесть операций с картой старыми именами — сервер переводит их в операции 4.3+
   (docs/models/acquiring.md, «Старая схема»); `ИтогиДняПоКартам`, `АварийнаяОтменаОперации` совпадают с новыми.
3. **Принтер чеков и дисплей (0.7.5).** Чек строками `ОткрытьЧек`…`ЗакрытьЧек` (docs/models/printers.md),
   `ПолучитьПараметрыВывода` дисплея. Весы (`ПолучитьВес`, `УстановитьВесТары`), дисплей, ТСД, весы с этикетками,
   принтер этикеток и RFID в старой и новой схеме называются одинаково и с теми же параметрами.
   Не делается `НапечататьОтчетСГашением` — он нужен только типу «ФискальныйРегистратор» (до 54-ФЗ), такого типа
   в Эмулконе нет.

**Прогон в демо-базе УТ 10.3.88.3 (БПО 3.1.10.48): 72 из 72** — tests/1c/README.md, обработка
`ТестЭмулкона103`. Все типы, кроме распознавания (его в БПО 3.1 нет), подключаются по старой схеме и
отвечают на команды синхронного `МенеджерОборудованияКлиент.ВыполнитьКоманду`: эквайринг старыми
именами (одобрение, экран терминала, отказ банка, сверка), события сканера и считывателя, весы, ТСД,
дисплей, RFID, весы и принтер этикеток.

- **ККТ через справочник в УТ 10.3.88.3 не подключается — дефект конфигурации, не драйвера.** При
  подключении ККТ БПО читает параметры регистрации из табличной части `ПараметрыРегистрации` справочника
  `ПодключаемоеОборудование` (`МодульМенеджера.ПолучитьПараметрыРегистрацииУстройства`), а в справочнике
  есть только `ОграничениеДоступа`: запрос падает до драйвера. Модулем драйвера БПО в обход справочника
  ККТ проходит: подключение, `ПолучитьПараметрыККТ`, текст, смена, X-отчёт, закрытие смены.
- **Фискальный чек** — командой `CheckFiscalization` модуля драйвера БПО, как документы УТ: `ВходныеПараметры[0]` —
  `ПараметрыОперацииФискализацииЧека()` с позициями и оплатами, БПО собирает CheckPackage
  (`ПолучитьXMLПакетДляФискализацияЧека_ТО`) и зовёт `СформироватьЧек`. Продажа за наличные, по карте и возврат
  пробиты с фискальным признаком. Параметры регистрации (версия ФФД, РН, ФН) БПО берёт из справочника — в
  прогоне они подставлены из ответа `ПолучитьПараметрыККТ`.
- Принтер чеков в этой БПО печатает текст документом (`НапечататьТекстовыйДокумент`); строки
  `ОткрытьЧек`…`ЗакрытьЧек` БПО шлёт только типу «ФискальныйРегистратор», которого в Эмулконе нет.

## Отличия БПО 3.3.4 от 3.2.9, найденные прогоном

- **Кассовые смены в базе.** БПО 3.3 ведёт смену по фискальному устройству (в УНФ — документ
  «Кассовая смена», реквизит «Фискальное устройство») и не шлёт `OpenShift`, пока считает смену
  открытой («Кассовая смена уже открыта.» — `ОборудованиеЧекопечатающиеУстройства.ПередОткрытиемКассовойСмены`).
  Сброс эмулятора через Control API при этом рассинхронизирует учёт — см. docs/models/kkt.md.
- **Параметры эквайринга** берутся конструктором `ПараметрыВыполненияЭквайринговойОперации()`:
  БПО 3.3 читает `ИдентификаторОперацииНаОборудовании`, которого нет в самодельной структуре.
- **Оплата картой с фискализацией** переписана (`ФискализацияЧекаСОплатойКартойАсинх`, команда
  `PayAndFiscalization`). В 3.3.4.30 она падает до драйвера: `ПодготовитьДанныеФискализацииСОплатой`
  передаёт подключение ККТ в `ПриПодготовкеДанныхОперации`, которая ждёт обёртку подключений
  («Поле объекта не обнаружено (ПодключениеОсновногоУстройства)»). Ошибка БПО, не драйвера.
- **Учёт ошибок драйвера.** К тексту ошибки стороннего драйвера 3.3 дописывает «снят с поддержки»
  вместо «не сертифицирован» — смысл тот же (component/README.md).
