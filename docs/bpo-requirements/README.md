## Что установлено

**Эквайринг** — [pos-terminal.md](pos-terminal.md): методы раздела 3.9, TerminalParameters, OperationParameters, что БПО передаёт и читает.

**Весы** — [scales.md](scales.md): электронные весы (3.1) и весы с печатью этикеток в режиме OFFLINE (3.2): методы, ScaleOptions, Data, GoodsTable, пакеты выгрузки, событие «Взвешивание».

**Устройства ввода и события** — [input-devices.md](input-devices.md): раздел 3.8, ExternalEvent, какие события БПО слушает по типам, дорожки считывателя, имя типа СчитывательМагнитныхКарт.

**Дисплей покупателя** — [display.md](display.md) (3.3). **ТСД** — [tsd.md](tsd.md) (3.4). **RFID** — [rfid.md](rfid.md) (3.10). **Распознавание** — [recognizer.md](recognizer.md) (3.11).

**Принтеры** — [printers.md](printers.md): принтер чеков (3.6) и принтер этикеток (3.7): методы, DocumentPackage, LabelsTable, пакеты этикеток и как их нумерует БПО.

**Методы** — [kkt-methods.md](kkt-methods.md): общие (раздел 2) и ККТ (3.5) с типами, позициями
и направлениями, сверены по документу 4.8 и коду БПО.

**Форма вызова** (код БПО). `Ждать ОбъектДрайвера.<РусскоеИмя>Асинх(п0, п1, …)`. Результат:
`Значение` (возвращаемое значение) и `Параметры[]` — все параметры после вызова. БПО читает
выходные позиции и иногда входные.

**Ревизия** — число (4008 = «4.8»). При ревизии > 4002 БПО подключает драйвер через
`ConnectEquipment`/`EquipmentTest`. Старой схемы (`SetParameter` + `Open`) в документе 4.8 нет.
**Эмулятор объявляет 4008.**

**Типы оборудования** — таблица «Тип оборудования» раздела 2: BarcodeScanner, CardReader, KKT,
ReceiptPrinter, CustomerDisplay, DataCollectionTerminal, POSTerminal, WeighingScales,
LabelPrintingScale, LabelPrinter, RFIDReader, Recognizer (плюс русские написания).
Сервер принимает их как есть (`models.EquipmentTypes`).

**Описание драйвера** содержит штатный атрибут `IsEmulator`: БПО сама знает, что драйвер —
эмулятор (ARCHITECTURE §10).

**Пакет драйвера:** `INFO.XML` (`drivers/component` с атрибутами progid, name, version, type) и
`MANIFEST.XML` (`bundle/component` с атрибутами os, arch, type). Разбор в БПО —
`ВнешниеКомпонентыСлужебный:1363` и `:1108`; требования — раздел 4 документа.
*Сведения о пакете собрал фоновый поиск, построчно ещё не перепроверены.*

**События** сканера и других устройств ввода — внешние события, без вызова методов
(раздел 3.8 документа; в БПО — `ПодключаемоеОборудованиеДрайверКлиент.ОбработатьСобытие` :1508).

## Решение по Device API (2026-10-08) — принято и реализовано

Параметры **позиционные**: компонента шлёт массив всех параметров вызова и записывает обратно
массив из ответа. `result` — возвращаемое значение (BOOL/LONG/null). `GetLastError` — обычная
команда, последнюю ошибку устройства помнит ядро сервера. Методы до `ConnectEquipment`
компонента обслуживает сама — у неё ещё нет адреса сервера.
Подробно — [protocol.md](../protocol.md) §1.1–1.2.

**Как БПО загружает драйвер** (код БПО 3.3.4.30):
- из INFO.XML берётся `progid`, а `Идентификатор` — часть после первой точки
  (`ВнешниеКомпонентыСлужебный:1371`);
- «Загрузить новый драйвер из файла» режет `type` из INFO.XML по «,» (и «;») и создаёт **по записи
  справочника «Драйверы оборудования» на каждый тип** с одним `ИдентификаторОбъекта`
  (`ДрайверыОборудования`, форма списка, `ЗагрузитьНовыйДрайверИзФайла_Завершение`). «Обновить
  драйвер» в карточке перезагружает компоненту по идентификатору и новых записей не создаёт — типы,
  добавленные в новой версии, появятся только после новой загрузки архива;
- объект создаётся как `"AddIn." + СимволическоеИмя + "." + Идентификатор`
  (`ВнешниеКомпонентыБПОКлиент:260`). Значит, `GetClassNames` и `RegisterExtensionAs` должны
  вернуть ту же вторую часть ProgID — у нас `EmulkonDriver`;
- описание драйвера БПО сначала запрашивает формой с одним XML-параметром. Если вызов бросил
  исключение — переходит к старой форме из 7 параметров (`ПодключаемоеОборудованиеДрайверКлиент:377–410`).
