# Проверка драйвера в 1С под Linux

Драйвер Эмулкона собирается и под Linux (`libEmulkonDriver_lin64.so`, x86_64): CI собирает его в manylinux_2_28
(glibc 2.28) и прогоняет модульные тесты и стенд «как платформа 1С» — без сервера и на живом сервере. Здесь —
проверка в **настоящей 1С под Linux**: тестовая ВМ Hyper-V на машине разработчика.

## ВМ без мастера (по умолчанию)

```powershell
tests\linux\new-vm.ps1            # облачный образ Ubuntu 24.04 → ВМ EmulkonUbuntu, снимок «чистая Ubuntu»
tests\linux\vm.ps1 "uname -a"     # команда в ВМ по SSH
tests\linux\vm.ps1 -Put <файл>    # файл в ВМ (домашний каталог emulkon)
tests\linux\new-vm.ps1 -Remove    # удалить ВМ
```

- Образ — `cloud-images.ubuntu.com/<release>/current`, сверка с `SHA256SUMS`. Hyper-V не читает qcow2, а qemu-img
  на Windows нет: `vmtool` (Go, только стандартная библиотека) переводит qcow2 в VHD и пишет ISO `CIDATA` для
  cloud-init (ISO 9660 + Joliet — монтировать ничего не нужно).
- cloud-init: пользователь `emulkon` **только с SSH-ключом** (`~/.ssh/emulkon_vm_ed25519`, создаётся один раз),
  sudo без пароля, Xvfb (1С без экрана). Пароль никто не вводит и он не задан.
- ВМ в сети «Default Switch» под именем `emulkon-linux.mshome.net`. Сервер Эмулкона этого компьютера для ВМ —
  адрес шлюза по умолчанию в ВМ (адрес «Default Switch» на компьютере), служба должна слушать сеть («Кассы в сети»).
- Права администратора не нужны, если Hyper-V доступен пользователю (так на машине разработки).

## Что нужно от человека

- **Платформа 1С для Linux** — `setup-full-<версия>-x86_64.run` (8.3.20 и новее) в папке на этом компьютере
  (скачать с ИТС или установщиком Апдейкона, `upd.imiron.ru/install`), и **лицензия** для ВМ. Скачивать с портала
  1С под учётной записью ИТС и активировать лицензию — дело человека.

Дальше без человека: `vm.ps1 -Put` дистрибутив и `install-1c.sh`, `sudo bash install-1c.sh ~`, затем
`check-driver.sh http://<шлюз>:8737` — пакет драйвера с сервера, SHA-256, библиотека Linux, `ldd`.

## Проверка в 1С

**Результат 17.10.2026:** УНФ 3.0.14.159, БПО 3.3.4.30, платформа 8.5.1.1529, Ubuntu 24.04 — **128 из 128** шагов, все
12 типов оборудования ([tests/1c/RESULTS.md](../1c/RESULTS.md)). Первый прогон нашёл ошибку драйвера: при русской
локали вес с весов приходил нулём (числа JSON зависели от локали) — исправлено.

Перекрёстно, 17.10.2026, обе — 128 из 128:

- 1С под Linux (ВМ) → сервер на Windows (служба этого компьютера, через туннель SSH `-R 8737`);
- 1С на Windows (УНФ 3.0, 8.5.1.1529, `tests\1c\run.ps1 -Server http://127.0.0.1:8738`) → сервер на Linux (пакет `.deb` в
  ВМ, служба systemd, туннель `-L 8738:127.0.0.1:8737`); в журнале Linux-сервера — сессии драйвера `windows x86_64`.

```powershell
tests\linux\run-1c.ps1 -Screen     # туннель и экран ВМ: http://localhost:6080/vnc.html (лицензия — человек, один раз)
tests\linux\run-1c.ps1             # прогон ТестЭмулкона: отчёт — tests\linux\build\report-<база>.txt
```

Подготовка ВМ (один раз; снимок «1С 8.5.1.1529 + лицензия разработчика + УНФ 3.0»):

1. Платформа: `vm.ps1 -Put server64_<версия>.zip`, распаковать `setup-full-*.run` в `~/1c`, `sudo bash install-1c.sh ~/1c`
   (клиент, `ibcmd`, зависимости; встроенная `libstdc++` 1С отключается — на Ubuntu 24.04 клиент с ней не стартует).
2. База: `ibcmd infobase create --data=~/bases/EmulkonTest_UNF --restore=<.dt>` — файловая база в `db-data`. Первый запуск
   демо-базы долгий (первичное обновление данных) — до прогона.
3. Лицензия — community-лицензия разработчика (developer.1c.ru): `run-1c.ps1 -Screen`, в окне 1С «Активировать
   комьюнити-лицензию», логин и пароль вводит человек.
4. «Предупреждение безопасности» на открытие обработки — отключено только в ВМ и только для баз `EmulkonTest`:
   `DisableUnsafeActionProtection=.*EmulkonTest.*` в `/opt/1cv8/conf/conf.cfg` (тот же механизм, что
   `tests\1c\disable-unsafe-protection.ps1`; решение владельца).

Тонкости, найденные при первом прогоне:

- `УстановитьВнешнююКомпонентуАсинх` под Xvfb распаковывает компоненту в `~/.1cv8/1C/1cv8/ExtCompT`, но не возвращает
  управление (сообщение «установлена» не появляется). Повторный запуск находит компоненту установленной и идёт дальше.
- Новая сборка драйвера той же версии в `ExtCompT` сама не ставится (1С помнит компоненту по имени файла) — для проверки
  исправления файл подменялся в `ExtCompT` вручную.
- УНФ во время маркировки спрашивает установку ExtraCryptoAPI и ходит в ГИС МТ — окна не мешают прогону, но держат 1С
  после итога: прогон заканчивается по таймауту, отчёт уже полный.

Что проверяем именно на Linux:

- загрузка `.so` платформой (`MANIFEST.XML`, `os="Linux"`) и ABI — те же методы, что на Windows;
- HTTP-клиент на сокетах: сессии, команды, поток событий (сканер, весы, экран терминала);
- самообновление: кэш `~/.cache/emulkon/driver/<версия>/`, переадресация через `dlopen` после перезапуска 1С;
- база из командной строки (`/proc/self/cmdline`), имя компьютера (`gethostname`).

## ВМ с рабочим столом (`-Desktop`)

`new-vm.ps1 -Desktop` — образ Ubuntu с рабочим столом для Hyper-V от Canonical (ВМ `EmulkonLinux`): первый запуск —
мастер Ubuntu в окне ВМ, имя и пароль вводит человек. Для ручной проверки с экраном; платформа — тем же
установщиком Апдейкона в терминале ВМ:

```bash
sudo bash -c "$(curl -fsSL https://upd.imiron.ru/1c.sh)" -- --version 8.3 --mode client
```
