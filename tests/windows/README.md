# Тестовая ВМ Windows — установщик под Defender (#20)

Стенд для проверок установщика Эмулкона на чистой системе: срабатывания Defender, установка, удаление,
поведение у другого пользователя. ВМ Hyper-V на диске D: (решение владельца).

## Создание

```powershell
tests\windows\new-vm.ps1 -Iso D:\…\ru-ru_windows_server_2022….iso   # создать EmulkonWin, Windows ставится сама
# в окне ВМ: «Сделать позже» на экране ключа, затем задать пароль администратора (человек)
tests\windows\new-vm.ps1 -Snapshot                                  # после установки: убрать DVD, снимок
tests\windows\new-vm.ps1 -Remove                                    # удалить ВМ и диск
```

- Windows Server 2022 Standard (рабочий стол), русский, Defender включён. Поколение 1 (BIOS).
- Установка без мастера — `autounattend.xml` + `emulkon-setup.ps1` на втором DVD (его собирает `vmtool iso`).
  Ключ продукта не задаётся (розничный образ его не берёт) — Windows без активации, для проверок хватает.
- OpenSSH — из `OpenSSH-Win64-*.msi` (Microsoft) в `D:\.Hyper-V\Emulkon\cache`, подпись проверяется; вход только
  по ключу `~/.ssh/emulkon_vm_ed25519` (его же использует ВМ Linux). Пароль администратора знает только человек.
- Снимок «чистая Windows Server 2022 + OpenSSH» — к нему откатываться перед каждым прогоном.

## Работа

```powershell
tests\windows\vm.ps1 '(Get-Service Emulkon).Status'         # команда в ВМ по SSH (вход «Администратор»)
tests\windows\serve.ps1 -Dir dist\downloads                 # на хосте: раздать файлы в ВМ по HTTP
# в ВМ: Invoke-WebRequest http://172.27.144.1:8099/EmulkonSetup_0.9.3.exe -OutFile C:\...
```

scp в этой ВМ ненадёжен (встроенный OpenSSH 8.1 и OpenSSH 10 из MSI мешают друг другу) — файлы передаём по HTTP
через `serve.ps1` (TcpListener, без прав администратора).

## Что выяснено про Defender (#20, прогон 0.9.3)

Срабатывание `Trojan:Win32/Bearfoos.A!ml` — **облачная ML-оценка в реальном времени при запуске**, не статическая
подпись:

- скан по требованию (`MpCmdRun -Scan`) установщика и всех вложенных бинарников — чисто;
- бинарники, скачанные по отдельности, — не трогаются;
- запуск установщика с меткой «из Интернета» и без неё — на чистом снимке проходит;
- но полная установка то ловится (3 раза в карантин), то нет — зависит от облака в момент запуска.

Вывод: перебирать устройство файла бесполезно, цель движется. Рычаги — подпись кода (#11), отправка в Microsoft
как ложное срабатывание, накопление репутации.
