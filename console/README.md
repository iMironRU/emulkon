# Оснастка MMC «Эмулкон» (Windows x64)

`EmulkonSnapIn.dll` — консоль управления Эмулконом в стиле Windows: открывается из меню «Пуск»
(«Эмулкон — консоль») и из Панели управления. Ставит и регистрирует её установщик
(`C:\Program Files\Emulkon\console\`). Что где делается — в оснастке, вебе или трее — docs/local-install.md §5,
этапы оснастки — §4.1.

## Что есть (этапы 1–4)

- **Эмулкон** — сводка: служба, версии сервера и консоли, адрес, веб-интерфейс, режимы доступа, число
  устройств и рабочих мест. «Действие → Обновить» перечитывает.
- **Служба** — состояние, тип запуска, учётная запись, команда, адрес, кассы в сети, токены, данные и журнал.
  «Действие» (и панель действий): запустить, остановить, перезапустить; выдать и снять токены управления и
  устройств; токен управления для консоли; открыть веб-интерфейс. «Свойства» — всё это на странице «Общие»
  и флажок «Сервер для касс в сети» (через `EmulkonSetup.exe /modify`). Подробно — docs/local-install.md §4.1.
- **Рабочие места** — список; «Действие»: выдать и отозвать токен, новое рабочее место; «Свойства» (двойной
  щелчок): подпись, заметка, токен, базы 1С, принтеры, устройства.
- **Устройства** — список; «Действие»: сбросить настройки, удалить; «Свойства»: подпись, заметка, сведения,
  вкладка «Состояние» (только чтение).
- **Сценарии** — список правил с условием и действием словами; «Действие»: включить, выключить, удалить;
  у раздела — выгрузить и загрузить сценарии (JSON); «Свойства» — правило целиком.
- **Журнал** — последние 500 записей, новые сверху; «Отбор…», «Сбросить отбор», «Выгрузить журнал…»
  (JSON Lines); «Свойства» — запись целиком.
- **Справка → О программе** — версия и поставщик.

Данные: состояние службы из SCM, настройки службы из `HKLM\Software\Emulkon\Server` (политика
`HKLM\Software\Policies\Emulkon` важнее), остальное — Control API сервера (`/control/v1/info`, `devices`,
`workstations`) с таймаутом 2 с и токеном консоли, если он есть. Токен сам нигде не хранится: в реестр —
только SHA-256, в консоли — в памяти до закрытия.

## Устройство

- `src/snapin.cpp` — COM без ATL: `IComponentData` (дерево), `IComponent` (правая панель: список или
  стандартное окно сообщения MMC), `IDataObject` (тип узла, имя, CLSID), `ISnapinAbout`, фабрика,
  `DllRegisterServer` / `DllUnregisterServer`.
- `src/summary.cpp`, `src/system.cpp` — данные без COM: адрес, разбор ответов, строки списков, SCM, реестр,
  HTTP (WinHTTP и JSON — общие с компонентой). `src/admin.cpp` — действия: служба, токены (BCrypt), запись
  хешей, мастер «Изменить». Тесты — `tests/unit.cpp`.
- `src/inventory.cpp` — рабочие места и устройства: разбор ответов, таблицы, время; запросы — `apiRequest`
  (адрес службы и токен консоли; PATCH и PUT добавлены в общий HTTP-клиент компоненты).
- `src/records.cpp` — сценарии и журнал: условие и действие словами, файл сценариев, загрузка, разбор журнала,
  выгрузка журнала потоком, JSON с отступами для свойств.
- `src/dialogs.cpp` — окна: свойства службы, рабочего места и устройства, страница «только чтение», ввод
  строки, новый токен, выбор файла. Шаблоны — в памяти, без .rc.
  Страница свойств MMC работает в своём потоке: интерфейсы MMC из неё не вызываются, только
  `MMCPropertyChangeNotify` → `MMCN_PROPERTY_CHANGE` → обновление списков в потоке консоли.
- GUID: оснастка `{1C4354F7-8B1F-4FF0-912D-50493CBE677C}`, «О программе»
  `{BD3F6610-A1AB-4AB0-9B2F-9A76B5D41F10}`, типы узлов — корень `{23A02B6E-…}`, раздел `{3F874E3C-…}`.
  Те же GUID — в `setup/src/console.cpp` (удаление регистрации и текст `Emulkon.msc`).

Подводные камни MMC:
- MMC спрашивает имя и тип узла (`CCF_DISPLAY_NAME`, `CCF_NODETYPE`) **до** `IComponentData::Initialize` —
  форматы буфера регистрируются при создании объекта данных. Иначе MMC падает в `mmcndmgr.dll`.
- Картинки «О программе» MMC использует и после освобождения объекта — они живут, пока загружена DLL.
- `MMC20.Application` → `Document.SnapIns.Add` на Windows 11 падает на любой оснастке; консоль `Emulkon.msc`
  установщик пишет готовым XML.

## Сборка и отладка

```powershell
console\build.ps1          # DLL, модульные и живой тест → console\dist\EmulkonSnapIn.dll (корневой build.ps1 кладёт её в dist\)
console\build.ps1 -NoLive  # без живого теста
```

**Живой тест** (`tests/live.ps1` → `tests/live.cpp`) поднимает отдельный сервер (`dist\emulkon.exe`, а нет его —
собирает) на 127.0.0.1:8799 с временными данными и случайными токенами управления и устройств и прогоняет те
же запросы, что окна консоли: сводка без токена и с ним; устройства заводит «драйвер» (`POST /api/v1/sessions`);
токен рабочего места — выдать, подключиться с ним, отозвать, подключиться нельзя; новое рабочее место; подпись
и заметка; сброс и удаление устройства; журнал — действия видны, токенов нет. Рабочая служба не трогается:
консоль идёт на адрес из `EMULKON_CONSOLE_URL`. Вне теста не задавать.

**Проверка окон** (`tests/ui-live.ps1`, от администратора, на машине разработки с установленным Эмулконом)
открывает установленную консоль и нажимает кнопки сообщениями окнам (`WM_COMMAND`, без мыши и клавиатуры):
«Служба → Свойства» — выдать токен управления (окно токена, «Копировать», в реестре только SHA-256, Control API
без токена — 401), токен устройств (драйвер без него — 401), снять оба; остановить, запустить, перезапустить;
«Кассы в сети» — включить через «Применить» (Network=1, правило брандмауэра, служба слушает все адреса) и
выключить; свойства рабочего места — подпись и заметка; сценарии — выключить, удалить, окна выгрузки и
загрузки; журнал — отбор, сбросить отбор, окно выгрузки. Пункты с модальным окном зовутся из второго потока:
вызов автоматизации MMC ждёт закрытия окна (поэтому `-MTA`). В конце возвращает как было: без токенов, сеть —
как до теста, тестового правила нет. Меняет установленную службу — не для чужих машин.

Окна выбора файла Windows 11 рисует DirectUI: поля «Имя файла» не видно ни сообщениям окнам, ни UI Automation,
поэтому тест только проверяет, что окно открылось, и жмёт «Отмена» (подставить имя не вышло — тоже «Отмена»:
иначе файл уйдёт под именем по умолчанию в последнюю папку пользователя). Содержимое выгрузок и загрузку
проверяет живой тест.

```powershell
powershell -MTA -ExecutionPolicy Bypass -File console\tests\ui-live.ps1 -Out ui-live.txt   # от администратора
```

Журнал вызовов MMC: собрать с `-DEMULKON_SNAPIN_TRACE=ON` (отдельным каталогом сборки), подложить DLL в
`C:\Program Files\Emulkon\console\` (права администратора) — вызовы пишутся в `%TEMP%\emulkon-snapin.log`.
