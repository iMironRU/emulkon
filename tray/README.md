# Трей Эмулкон (Windows)

Значок сервера эмуляции в области уведомлений рядом с часами. Показывает каждый
«напечатанный» эмулятором чек всплывающим окном и при желании печатает его на настоящий
принтер Windows. Ставится на рабочее место кассира. Сервер при этом может работать где
угодно: локально, на стенде, в Docker.

## Что умеет

- **Значок.** Оранжевая «Э» — связь с сервером есть, серая — связи нет; причина видна в
  подсказке и в меню. Щелчок левой кнопкой показывает последний чек.
- **Всплывающее окно** в правом нижнем углу при каждом документе устройства: чек, отчёты
  смены, внесение и выплата, текстовый документ (и с принтера чеков), копия чека, слип, этикетки весов и принтера этикеток. В заголовке — вид документа,
  ФД, устройство, рабочее место и время. Окно не забирает фокус у 1С и само закрывается
  через заданное время (по умолчанию 10 с); пока мышь над окном — не закрывается.
  Колесо мыши прокручивает длинный чек, щелчок закрывает окно.
- **Экран эквайрингового терминала.** Когда 1С проводит оплату картой на этом рабочем месте,
  поверх 1С открывается окно терминала: сумма, отсчёт, выбор карты (МИР, VISA, Mastercard,
  UnionPay, СБП) и кнопки «Приложить карту», «Отказ банка», «Недостаточно средств», «Неверный ПИН»,
  «Отмена». Ответ уходит на сервер, 1С получает результат, окно показывает «ОДОБРЕНО» или отказ
  и закрывается само. Закрыть окно — не значит отменить: вернуть его можно пунктом меню
  «Показать экран устройства».
- **Экран весов.** Если весы на этом рабочем месте спрашивают вес при каждом взвешивании
  (`weight_mode=ask`), на «Получить вес» в 1С открывается окно весов: поле «Вес, кг» (можно
  через запятую), «Взвесить» и «Отмена». 1С получает введённый вес.
- **Печать на принтер** — любой принтер Windows: чековый, офисный, «Microsoft Print to PDF».
  Шрифт подгоняется под ширину печатной области, поэтому лента 58/80 мм и A4 печатаются
  одинаково аккуратно. Для PDF/XPS-принтеров можно задать каталог — тогда файлы
  сохраняются без диалога.
- **Показывать ли и печатать ли — настройка устройства, а не трея.** В карточке устройства
  веб-интерфейса («Показ и печать на кассе»): показывать на экране кассы, печатать на принтер,
  какой принтер, что печатать (чеки, коррекции, копии, отчёты, нефискальные, слипы, этикетки) и
  «Напечатать последний документ». Сервер кладёт решение в запись журнала, трей выполняет
  (ARCHITECTURE §4.3). Принтеры этого компьютера трей сам сообщает серверу при подключении —
  из них карточка предлагает выбор. Пункт меню «Показ и печать чеков — в карточке устройства…»
  открывает веб-интерфейс.
- **Сканер «как клавиатура».** Если у сканера или считывателя в карточке выбрано «как клавиатура»,
  трей после паузы вводит код в активное окно — как настоящий сканер в режиме USB HID (запись
  `device.keyboard`). В окно, запущенное от администратора, Windows ввод не пропускает.
- **Служба Emulkon** (установка на машину, docs/local-install.md): в меню её состояние и «Перезапустить
  сервер», «Остановить» или «Запустить» — без UAC (пользователи могут управлять службой). Остановленную
  службу трей поднимает сам только при своём запуске; если связь была и пропала — сервер остановили
  намеренно, трей его не трогает. **Обслуживание…** — мастер «изменить, восстановить, удалить» (UAC).
- **Локальный сервер** — только когда службы нет (запуск из каталога разработки): «Запустить локальный
  сервер» / «Остановить» — `emulkon.exe` с адресом из настроек, ищется рядом с треем или в `server\bin`
  проекта; «Запускать локальный сервер вместе с треем» (`ServerAutostart`): трей поднимает сервер, если тот
  не отвечает, и останавливает свой при выходе.
- **Веб-интерфейс** и **страница загрузок** (драйвер для 1С, установщик) — пункты меню.
- **Проверка работы…** — `EmulkonSetup.exe /check` рядом с треем (в установленном Эмулконе).
- **Запуск при входе в Windows** — для всех пользователей его ставит установщик (`HKLM\…\Run`, меняется в
  «Обслуживании»); без этого — переключатель в меню (ключ `HKCU\…\Run`).

## Откуда трей берёт чеки

Модель на сервере каждый «напечатанный» документ пишет в журнал записью `device.print`.
Трей подписан на живой поток журнала:
`/control/v1/journal/stream?method=device.print,device.reprint,device.keyboard,device.prompt,device.prompt_done&workstation_id=<рабочее место>`
— документы и экран устройства: терминал, весы (docs/protocol.md §2.0).
Связь трей держит сам: переподключается, а после обрыва дочитывает пропущенное по курсору
(дочитанное не всплывает, только запоминается как последний чек).

**Рабочее место.** По умолчанию — имя этого компьютера. Так же по умолчанию называет рабочее
место и компонента-драйвер, поэтому на кассе ничего настраивать не нужно. Значение `*` —
показывать документы всех рабочих мест: удобно на машине тестировщика или разработчика.

## Настройки

`%APPDATA%\Emulkon\tray.ini` — меняются из меню («Настройки…» и переключатели). Здесь только трей и
сервер; показ и печать документов — в карточке устройства:

| Ключ | По умолчанию | |
|---|---|---|
| `ServerURL` | `http://127.0.0.1:8737` | адрес сервера |
| `ControlToken` | — | `EMULKON_CONTROL_TOKEN`, если на сервере задан |
| `Workstation` | имя компьютера | `*` — все рабочие места |
| `PopupSeconds` | `10` | сколько секунд держать всплывающее окно |
| `PrintOutputDir` | — | для PDF/XPS-принтеров: сохранять в этот каталог без диалога |
| `ServerExe`, `ServerData` | — | локальный сервер |
| `ServerListen` | из `ServerURL` | адрес прослушивания своего сервера; `0.0.0.0:8737` — кассы в сети |
| `ServerAutostart` | `0` | без службы: поднимать свой сервер, если сервер не отвечает (установщик 0.8.0 выключает — сервер служба) |

Лог трея: `%LOCALAPPDATA%\Emulkon\tray.log` — подключение, полученные документы, печать.

## Сборка и запуск

```powershell
.\build.ps1                      # x64, тесты, tray\dist\EmulkonTray.exe
.\dist\EmulkonTray.exe            # запуск (один экземпляр)
.\dist\EmulkonTray.exe --exit     # закрыть запущенный трей (ждёт, пока он закроется)
```

Самопроверки без экрана и принтера:
- `--render out.bmp` рисует окно с образцом чека;
- `--render-terminal out.bmp` рисует окно терминала «приложите карту»;
- `--render-scales out.bmp` рисует окно весов «положите товар»;
- `--print "<принтер>" out.pdf` печатает образец.

Трей использует JSON и текстовые функции компоненты (`component/src`). Внешних зависимостей
нет, CRT статическая.
