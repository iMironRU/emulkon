# Участие в разработке

Спасибо, что хотите помочь Эмулкону. Ошибки и предложения — в [Issues](https://github.com/iMironRU/emulkon/issues),
изменения — pull request'ом в `main`.

## Что важно знать заранее

- **Контракт БПО первичен.** Имена методов, параметры и коды ошибок драйвера берутся из требований БПО
  ([docs/bpo-requirements/](docs/bpo-requirements/README.md)), а не придумываются. Нет метода в таблице — нет его в модели.
- **Документы — источник правды.** Изменили поведение модели — обновите `docs/models/<тип>.md` в том же коммите;
  изменили API — `docs/openapi.yaml` и `docs/protocol.md`. Расхождение кода с документом: сначала документ, потом код.
- **Клиент глупый, сервер умный.** Драйвер знает только «метод, параметры, ответ, событие»; логика — на сервере.
- **Всё в журнале**, токены и секреты — никогда.
- **Только тестовые данные**: реальные номера карт и ПИН не принимаются и не хранятся.
- **Эмулятор узнаваем**: «ЭМУЛЯТОР» в названии драйвера, в UI, на чеках и слипах.

## Код

- Комментарии и сообщения об ошибках — по-русски, идентификаторы — латиницей.
- Go: ошибки заворачиваются с контекстом (`fmt.Errorf("открыть журнал: %w", err)`), без внешних зависимостей, пока
  можно обойтись стандартной библиотекой.
- C++: только ABI MSVC (clang-cl), исключения не выпускаются в платформу 1С, строки для 1С — через `IMemoryManager`.
- Веб-интерфейс — статика без сборки; данные от устройств выводятся только через `textContent`.
- Тесты обязательны для моделей, движка сценариев и протокола.

## Проверка перед pull request

```powershell
cd server; go build ./...; go vet ./...; go test ./...   # сервер
.\build.ps1                                               # всё: сервер, драйвер, трей, консоль, установщик + тесты
```

CI делает то же самое на Windows (GitHub Actions). Для сборки драйвера нужен SDK Native API 1С — в CI он берётся
из секрета репозитория, поэтому в pull request'ах из форков собираются сервер, трей и консоль, а драйвер и
установщик — после слияния.
