# Установщик Эмулкона (Windows x64)

`EmulkonSetup_<версия>.exe` ставит Эмулкон на компьютер для всех пользователей: сервер эмуляции —
службой Windows, трей — каждому пользователю, драйвер для 1С — в отдельную папку. Нужны права
администратора (Windows спросит при запуске). Программа регистрируется в «Установленных приложениях» и
оттуда же удаляется. Перед установкой и после неё установщик проверяет, что всё может работать. Устройство
и решения — docs/local-install.md.

Скачать: страница загрузок любого сервера Эмулкона, `http://<сервер>:8737/downloads`, или
`dist\EmulkonSetup.exe` после сборки. Подписи кода нет: Windows SmartScreen может предупредить о
неизвестном издателе — «Подробнее» → «Выполнить в любом случае».

## Что ставится

| Где | Что |
|---|---|
| `C:\Program Files\Emulkon\bin\` | `emulkon.exe` (сервер — служба Emulkon), `EmulkonTray.exe` (трей), `EmulkonSetup.exe` (удаление и проверка) |
| `…\Emulkon\console\` | `EmulkonSnapIn.dll` — оснастка MMC «Эмулкон», `Emulkon.msc` — готовая консоль (console/README.md) |
| `…\Emulkon\1C\driver\` | драйвер для 1С: `EmulkonDriver_<версия>.zip` — в «Драйверы оборудования», DLL x64/x86 — для самообновления |
| `…\Emulkon\1C\epf\` | обработки для 1С (пока пусто) |
| `…\Emulkon\setup\` | `EmulkonSetup_<версия>.exe` — поставить Эмулкон на соседний компьютер |
| `C:\ProgramData\Emulkon\` | данные службы: `data\` (устройства, рабочие места, сценарии, журнал), `logs\service.log`, `backup\`, `updates\` |
| служба `Emulkon` | «Эмулкон — сервер эмуляции оборудования»: автозапуск, учётная запись LocalService, перезапуск при сбое |
| `HKLM\Software\Emulkon\Server` | настройки службы (docs/local-install.md §2.1): `Network` — сервер для касс в сети и др. |
| журнал «Приложение» | источник `Emulkon`: запуск, остановка, сбои службы |
| меню «Пуск» → «Эмулкон» (общее) | консоль, трей, веб-интерфейс, загрузки для 1С (папка `1C`), проверка работы |
| Панель управления | элемент «Эмулкон» в «Оборудование и звук» и «Программы» — открывает консоль (оснастку MMC) |
| `HKLM\Software\Microsoft\MMC\SnapIns` | регистрация оснастки «Эмулкон»; COM-класс — в `HKLM\Software\Classes\CLSID` |
| `HKLM\…\Run` → `EmulkonTray` | автозапуск трея у каждого пользователя (флажок в мастере) |
| `HKLM\…\Uninstall\Emulkon` | запись в «Установленных приложениях» |
| у пользователя | `%APPDATA%\Emulkon\tray.ini` — настройки трея, `%LOCALAPPDATA%\Emulkon\driver\` — кэш самообновления драйвера |

Права: в `ProgramData\Emulkon` пишут служба и администраторы, пользователи только читают; ключ `Server` читает
служба, пользователи — нет (там будут хеши токенов). Запускать и останавливать службу могут и обычные
пользователи — трей перезапускает сервер без UAC; менять её параметры — только администраторы.

Флажок «Сервер для касс в сети» пишет `Network=1` (служба слушает `0.0.0.0:8737`) и разрешает входящие TCP 8737
для `emulkon.exe` в брандмауэре. Токены для сети задаются хешами SHA-256: `DeviceTokenHash`,
`ControlTokenHash` в том же ключе; выдаются в консоли: «Эмулкон → Служба → Свойства» (docs/local-install.md §4.1).
Если токенов нет, мастер при включении сети предупреждает.

Повторный запуск установщика — обновление на месте: служба останавливается, трей закрывается (у других
пользователей — через Restart Manager, как у MSI), файлы заменяются, данные и настройки сохраняются. Файлы, которые
держит программа, которую установщик не закрывает (консоль MMC — обновление запустили из неё, 1С), мастер находит
до остановки службы (#24): шаг «Занятые файлы» называет программу — закройте её и нажмите «Проверить снова».

**«Исправить и обновить».** Помехи, которые мастер может устранить сам, проверки помечают (`Item::fix`); если все
ошибки из таких, главная кнопка — «Исправить и обновить» («…и установить»). Она спрашивает со списком действий,
устраняет (`fixBlockers`), проверяет заново и ставит. Сейчас это открытая консоль «Эмулкон» (`mmc.exe` с оснасткой —
закрывается как крестиком, ждём до 15 с) и другой сервер Эмулкона на порту 8737 (останавливается). 1С и чужие
программы мастер не закрывает: в них могут быть несохранённые данные. Без окна (`/quiet`) ничего не исправляется.

Установщик избегает приёмов, которые антивирус считает уклонением от защиты (#20): правило брандмауэра — через
API брандмауэра Windows, а не `netsh`; процессы — через Restart Manager, без `SeDebugPrivilege`; занятые файлы
не переименовываются; никаких скрытых `cmd`. Консоль скачивает обновление в «Загрузки» пользователя с меткой
«из Интернета», как браузер.

**Прежняя установка в профиле пользователя** (до 0.8.0, `%LOCALAPPDATA%\Programs\Emulkon`) находится
автоматически: данные сервера из `%LOCALAPPDATA%\Emulkon\data` переносятся в `ProgramData\Emulkon\data` (если там
ещё пусто), копия — в `backup\from-profile-<дата>`; старая программа, её ярлыки, автозапуск и запись в
«Установленных приложениях» удаляются.

## Проверки

**Перед установкой:**
- Windows и разрядность;
- права на запись в каталог и свободное место;
- кто занимает порт 8737: свободен, служба Эмулкона, сервер прежней установки, другой сервер Эмулкона или чужая программа;
- прежняя установка в профиле;
- найденные версии 1С:Предприятия и их разрядность.

Ошибка (`✖`) блокирует установку, предупреждение (`⚠`) — нет.

**После установки и по `/check`** (ярлык «Эмулкон — проверка работы»):
- файлы на месте;
- служба Emulkon работает, трей запущен;
- сервер отвечает, и это та же версия;
- страница загрузок публикует драйвер;
- драйвер x64 загружается, как его грузит платформа 1С (Native API), и проходит
  «Тест устройства» на сервере. Это сквозная проверка: DLL, WinHTTP, Device API.

## Обслуживание: изменить, восстановить, удалить

В «Параметры → Приложения → Эмулкон» кнопка **«Изменить»** открывает мастер обслуживания
(`bin\EmulkonSetup.exe /maintain`) с тремя вариантами (docs/local-install.md §3):

- **Изменить** — автозапуск трея и сервер для касс в сети (с правилом брандмауэра). Файлы и данные не
  трогаются; если сменился адрес, служба перезапускается.
- **Восстановить** — файлы программы заново из этого мастера, служба, права, ярлыки, записи реестра,
  затем проверка работы. Данные и настройки не трогаются.
- **Удалить** — как «Удалить» в «Параметрах».

Отдельной кнопки «Восстановить» Windows не-MSI программам не показывает, поэтому она внутри мастера.

## Ключи

```
EmulkonSetup.exe                 мастер установки или обновления
EmulkonSetup.exe /maintain       мастер обслуживания (так его открывает «Изменить»)
EmulkonSetup.exe /modify         изменить параметры установленного (в окне — обслуживание с выбранным «Изменить»)
EmulkonSetup.exe /repair         восстановить установленное
EmulkonSetup.exe /check          проверка работы установленного
EmulkonSetup.exe /uninstall      удаление
  /quiet           без окон: итог — код возврата (0 — успех, 1 — ошибки, 2 — неверные ключи)
  /log <файл>      отчёт в файл (UTF-8)
  /dir <каталог>   каталог установки (по умолчанию C:\Program Files\Emulkon)
  /autostart, /noautostart   запускать ли трей при входе в Windows
  /network, /nonetwork       сервер для касс в сети (0.0.0.0:8737, правило брандмауэра) или только этот компьютер
                   для /modify и /repair непереданное берётся из установленного; /maintain без окна — ошибка 2
  /norun           не запускать трей после установки
  /purge           при удалении — и данные: ProgramData\Emulkon, настройки трея и кэш драйвера этого пользователя
```

`EmulkonSetup.exe` — оконная программа: PowerShell и `cmd` не ждут её через `&` или по имени, код возврата не
доходит, а следующая команда идёт одновременно (так `/check` сразу за `/repair` застаёт службу остановленной на
замену файлов). Из скриптов — с ожиданием:

```powershell
$p = Start-Process EmulkonSetup.exe -ArgumentList "/repair", "/quiet", "/log", "C:\Temp\repair.log" -Wait -PassThru
$p.ExitCode
```

В `cmd` — `start /wait EmulkonSetup.exe /check /quiet /log …`.

Удаление из «Параметров» запускает `bin\EmulkonSetup.exe /uninstall`: служба останавливается и удаляется,
затем файлы, ярлыки и записи. Свой exe Windows удалить не даёт: мастер, `bin` и опустевший каталог удаляются
при перезагрузке Windows. Данные в `ProgramData\Emulkon` остаются, если не выбрано «Удалить и
данные». Драйвер в базах 1С удаляется в самой 1С.

## Сборка

```powershell
.\build.ps1          # в корне: сервер, драйвер, трей, оснастка и установщик → dist\
setup\build.ps1      # только установщик из уже собранного dist\
```

Файлы для установки зашиты в exe ресурсами `RCDATA` (`src/setup.rc.in`). Манифест —
`requireAdministrator`: установка на машину и служба. Логика без окна (`src/paths.cpp`, `install.cpp`,
`service.cpp`, `checks.cpp`, `probe.cpp`) отделена от окна (`src/main.cpp`). Тесты — `tests/unit.cpp`.
